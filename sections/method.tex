\section{HAT: Hippocampus-Augmented Transformer}
\label{sec:method}

We introduce \textbf{Hippocampus-Augmented Transformer (\HAT)}, a memory-centric continual learning architecture for language models that separates \emph{interaction}, \emph{memory consolidation}, and \emph{model adaptation}.
The motivating observation is that most online interactions are not equally useful for future learning: many are routine, redundant, or already within the model's competence, whereas a small subset exposes epistemic gaps, user-specific corrections, or reusable knowledge.
Rather than updating model parameters after every turn, \HAT first decides whether an interaction should become a persistent training signal and only later replays accepted memories during an offline slow-wave-sleep (SWS) phase.

The design follows a hippocampal--neocortical division of labor.
The \textbf{Cortex} $\modeltheta$ is the online language model that produces responses and exposes confidence information.
The \textbf{Hippocampus Agent} $\hippocampus$ converts selected interactions into compact, canonical memory traces and decides how each trace should modify long-term memory.
The \textbf{Neocortex} $\neocortex$ is an appendable and revisable store of curated traces, indexed by semantic embeddings for nearest-neighbor routing.
The \textbf{SWS Trainer} $\sws$ samples high-value traces from the Neocortex and converts them into supervised replay batches for parameter-efficient adaptation.
Optionally, an external \textbf{Oracle} $\oracle$ is queried only on high-uncertainty turns, providing budgeted supervision at the frontier of the model's competence.

\subsection{Selective Continual Consolidation}
\label{sec:method:formulation}

Let the wake stream at cycle $t$ be
\begin{equation}
  \mathcal{D}^{(t)} = \{x_i^{(t)}\}_{i=1}^{T_t},
  \qquad
  x_i = (c_i, q_i, y_i),
  \label{eq:wake_stream}
\end{equation}
where $c_i$ is optional conversational context, $q_i$ is the user query, and $y_i$ is the Cortex response.
User corrections are not assumed to arrive as a clean scalar label; in realistic chat settings they may appear as subsequent turns in the same session and must be interpreted in context.
HAT therefore maintains two distinct data regimes: raw session history, which preserves what happened, and curated Neocortex memory, which contains only authorized training traces.

The ideal memory update would retain the subset of experience that maximizes downstream utility under a bounded replay budget:
\begin{equation}
  \neocortex^{*(t)}
  =
  \argmax_{\neocortex' \in \mathcal{U}(\neocortex^{(t-1)},\mathcal{D}^{(t)})}
  \E_{(q,a)\sim p_{\mathrm{replay}}(\cdot\mid\neocortex')}
  \left[
    \Delta \loss_{\mathrm{future}}(\params; q,a)
  \right]
  \quad
  \mathrm{s.t.}\quad |\neocortex'| \le B,
  \label{eq:ideal_memory_update}
\end{equation}
where $\mathcal{U}$ is the set of admissible CREATE and REVISE operations.
The expected future loss reduction is unobservable at write time, so HAT replaces it with a structured surrogate:
\begin{equation}
  \underbrace{U(x)\ge\tau_w}_{\text{eligibility}}
  \quad\Longrightarrow\quad
  \underbrace{\hippocampus_{\mathrm{abs}}(x)}_{\text{canonical traces}}
  \quad\Longrightarrow\quad
  \underbrace{R(m,\neocortex)\in\{\textsc{Create},\textsc{Revise}\}}_{\text{semantic routing}}
  \quad\Longrightarrow\quad
  \underbrace{\mathrm{Write}(m,d)}_{\text{authorized memory transition}}.
  \label{eq:surrogate_pipeline}
\end{equation}
This factorization is the core methodological choice.
Uncertainty controls whether an interaction is worth spending consolidation compute on; abstraction produces canonical knowledge-level traces; geometric routing reconciles a trace with prior memory; and the write policy emits an explicit authority token required by the memory store.

\subsection{Wake--Sleep Decomposition}
\label{sec:method:wake_sleep}

At each cycle, HAT alternates between a wake operator $\mathcal{W}$ and a sleep operator $\mathcal{S}$:
\begin{align}
  \neocortex^{(t)}
  &=
  \mathcal{W}
  \left(
    \neocortex^{(t-1)}, \mathcal{D}^{(t)}; \modeltheta, \hippocampus, \oracle
  \right),
  \label{eq:wake_operator} \\
  \params^{(t+1)}
  &=
  \mathcal{S}
  \left(
    \params^{(t)}, \neocortex^{(t)}
  \right).
  \label{eq:sleep_operator}
\end{align}
The wake operator does not update model parameters.
It produces a sequence of accepted memory creations and revisions.
The sleep operator samples from the resulting memory and performs batched empirical risk minimization.
This decomposition avoids unstable online learning and makes the provenance of every replay example explicit.

% ────────────────────────────────────────────────────────────
\subsection{Cortex: Online Model and Uncertainty Gate}
\label{sec:method:cortex}

The Cortex is an autoregressive language model $\modeltheta$ with parameters $\params$.
Given context $c$ and query $q$, it generates
\begin{equation}
  p_{\params}(y \mid c,q)
  =
  \prod_{j=1}^{|y|}
  p_{\params}
  \left(y_j \mid c,q,y_{<j}\right).
  \label{eq:cortex_lm}
\end{equation}
In addition to generation, the Cortex provides an uncertainty score for the realized response.
When token log-probabilities are available, HAT uses one minus the geometric mean token probability:
\begin{equation}
  U(x)
  =
  1 -
  \exp
  \left(
    \frac{1}{|y|}
    \sum_{j=1}^{|y|}
    \log p_{\params}(y_j \mid c,q,y_{<j})
  \right),
  \qquad U(x)\in[0,1].
  \label{eq:logprob_uncertainty}
\end{equation}
High-probability responses yield $U(x)\approx 0$, whereas low-confidence responses yield larger uncertainty.
For backends that do not expose token log-probabilities, the implementation falls back to a calibrated constant, preserving the same interface while avoiding backend-specific failure modes.

Uncertainty is used as a computational gate:
\begin{equation}
  g(x)=\indicator{U(x) \ge \tau_w}.
  \label{eq:uncertainty_gate}
\end{equation}
Only turns with $g(x)=1$ are passed to the abstraction pipeline.
Confident routine interactions remain in raw session history but are not summarized, embedded, or written into curated memory.

% ────────────────────────────────────────────────────────────
\subsection{Hippocampus Agent: Abstraction, Routing, and Authorization}
\label{sec:method:hippocampus}

The Hippocampus Agent implements the wake-time transition from raw interaction to curated memory.
Its current instantiation consists of optional oracle correction, LLM-based trace abstraction, deterministic embedding routing, and an authorized write policy.

\subsubsection{Budgeted Oracle Consultation}
\label{sec:method:oracle}

When an Oracle is configured, HAT consults it only for high-uncertainty interactions:
\begin{equation}
  y^{\oracle}
  =
  \oracle(c,q)
  \quad\mathrm{if}\quad
  U(x) > \tau_{\oracle}.
  \label{eq:oracle_policy}
\end{equation}
If the Oracle returns a nonempty correction, the target response used for downstream abstraction is replaced by $y^{\oracle}$.
Thus external supervision is acquired selectively rather than distilled over all interactions.
This mechanism allocates teacher calls to examples on which the student is least reliable.

\subsubsection{Trace Abstraction}
\label{sec:method:abstraction}

For every eligible interaction, the abstractor maps a verbose turn into zero or more canonical memory traces:
\begin{equation}
  \{m_{i,k}\}_{k=1}^{K_i}
  =
  \hippocampus_{\mathrm{abs}}(c_i,q_i,y_i),
  \label{eq:trace_abstraction}
\end{equation}
where $K_i=0$ means that the turn is dropped.
Each trace has the structured form
\begin{equation}
  m
  =
  \left(
    q^{\star},
    a_{\mathrm{cortex}},
    a^{\star},
    r,
    \xi
  \right),
  \label{eq:trace_tuple}
\end{equation}
where $q^{\star}$ is a canonical query, $a_{\mathrm{cortex}}$ is the original model response, $a^{\star}$ is the replay target, $r$ is an optional rationale, and $\xi$ stores provenance such as session id, interaction ids, uncertainty, oracle usage, and routing metadata.

The production abstractor is a two-stage LLM judge.
First, a triage prompt predicts whether the turn contains a knowledge point worth remembering:
\begin{equation}
  b_i = T_{\phi}(c_i,q_i,y_i) \in \{0,1\}.
  \label{eq:triage}
\end{equation}
If $b_i=0$, no trace is emitted.
If $b_i=1$, an extraction prompt emits a JSON-structured set of independent knowledge points:
\begin{equation}
  \{(q^{\star}_{i,k}, a^{\star}_{i,k}, r_{i,k})\}_{k=1}^{K_i}
  =
  E_{\phi}(c_i,q_i,y_i).
  \label{eq:extract}
\end{equation}
This design permits a single user turn to yield multiple replay examples while filtering small talk, meta-comments, and uninformative exchanges.
Crucially, the abstractor does not decide whether a trace is new or should overwrite an existing memory; that decision is made by a deterministic embedding router.

\subsubsection{Geometric CREATE/REVISE Routing}
\label{sec:method:routing}

Let $e(q)\in\R^d$ denote an L2-normalized embedding of a canonical query, and let the Neocortex maintain a vector index
\begin{equation}
  \mathcal{I}^{(t)} = \{(\mathrm{id}_j, v_j) : v_j=e(q_j^{\star}),\; \|v_j\|_2=1\}.
  \label{eq:vector_index}
\end{equation}
For a candidate trace $m$ with query $q^{\star}$, HAT retrieves its nearest existing memory:
\begin{equation}
  j^{\star}
  =
  \argmax_{j \in \mathcal{I}^{(t)}}
  e(q^{\star})^{\top} v_j,
  \qquad
  \rho(m)=e(q^{\star})^{\top} v_{j^{\star}}.
  \label{eq:nearest_memory}
\end{equation}
Since all vectors are unit normalized, $\rho(m)$ is cosine similarity.
The routing rule is
\begin{equation}
  R(m)=
  \begin{cases}
    \textsc{Revise}(\mathrm{id}_{j^{\star}}), & \rho(m) \ge \tau_r, \\
    \textsc{Create}, & \rho(m) < \tau_r \text{ or } \mathcal{I}^{(t)}=\emptyset.
  \end{cases}
  \label{eq:create_revise}
\end{equation}
Equivalently, $1-\rho(m)$ is a semantic novelty measure, but HAT uses it for routing rather than as a linear term in the write score.
This separation is important: uncertainty answers whether the current turn is worth remembering, while geometric similarity answers whether it should become a new memory or revise an existing one.

On the \textsc{Revise} path, the matched trace is updated in place with the new canonical query, target response, rationale, and interaction provenance; the previous target is retained in trace history.
The vector index entry for the matched trace is updated with the new query embedding.
On the \textsc{Create} path, a new trace id is appended to the Neocortex and its embedding is appended to the vector index.

\subsubsection{Write Policy and Authorized Memory Transition}
\label{sec:method:write_policy}

The write policy maps trace-level signals to a scalar decision.
In the current implementation the score is the uncertainty of the originating interaction:
\begin{equation}
  s(m) = U(x(m)),
  \qquad
  d(m)=\left(m.\mathrm{id}, s(m), \tau_w, \indicator{s(m)\ge\tau_w}\right).
  \label{eq:write_decision}
\end{equation}
The decision $d(m)$ is an authorization token.
The Neocortex accepts a write only if the decision is positive and its trace id matches the candidate trace:
\begin{equation}
  \mathrm{Write}(m,d)
  \;\mathrm{is\ valid}\;
  \Longleftrightarrow
  d.\mathrm{accepted}=1
  \;\wedge\;
  d.\mathrm{trace\_id}=m.\mathrm{id}.
  \label{eq:write_token_contract}
\end{equation}
This explicit write-token contract enforces the boundary between raw chat logs and curated training data.
It prevents accidental persistence of unapproved interactions and makes the raw-to-curated transition auditable.

% ────────────────────────────────────────────────────────────
\subsection{Neocortex: Curated Long-Term Memory}
\label{sec:method:neocortex}

The Neocortex stores accepted traces as supervised fine-tuning rows plus sidecar metadata.
For each accepted trace $m_i$, the primary training record is
\begin{equation}
  z_i
  =
  \left(
    [({\tt user}, q_i^{\star}), ({\tt assistant}, a_i^{\star})],
    \mathrm{id}_i,
    s_i,
    \xi_i
  \right),
  \label{eq:sft_row}
\end{equation}
which is directly compatible with standard chat supervised fine-tuning pipelines.
The sidecar trace preserves richer information such as rationale, interaction history, oracle provenance, and routing similarity.

The memory update induced by a candidate trace can be written abstractly as
\begin{equation}
  \neocortex \leftarrow
  \begin{cases}
    \neocortex \cup \{m\}, & R(m)=\textsc{Create},\; d(m).\mathrm{accepted}=1, \\
    \mathrm{Revise}(\neocortex, j^{\star}, m), & R(m)=\textsc{Revise},\; d(m).\mathrm{accepted}=1, \\
    \neocortex, & d(m).\mathrm{accepted}=0.
  \end{cases}
  \label{eq:neocortex_transition}
\end{equation}
For replay, the Neocortex exposes priority sampling by write score:
\begin{equation}
  \mathrm{Sample}_k(\neocortex)
  =
  \TopK_{m\in\neocortex}\; s(m),
  \label{eq:priority_sample}
\end{equation}
with manual edit and delete operations treated as memory curation rather than new learning events.

% ────────────────────────────────────────────────────────────
\subsection{Replay Construction and Slow-Wave Sleep Training}
\label{sec:method:sws}

The Replay Builder converts each retained memory trace into one or more supervised examples.
The default builder emits a single instruction--response pair:
\begin{equation}
  \mathcal{R}(m)
  =
  \{(q^{\star}, a^{\star}, w, \mathrm{id}_m, o_m)\},
  \label{eq:replay_builder}
\end{equation}
where $w$ is an example weight and $o_m$ indicates whether the target was Oracle-derived.
At sleep cycle $t$, HAT samples traces from the Neocortex and constructs
\begin{equation}
  \replaybuf^{(t)}
  =
  \bigcup_{m\in \mathrm{Sample}_k(\neocortex^{(t)})}
  \mathcal{R}(m).
  \label{eq:replay_batch}
\end{equation}

The supervised SWS objective is the token-level negative log-likelihood over the replay batch:
\begin{equation}
  \loss_{\mathrm{sup}}(\params;\replaybuf)
  =
  -
  \frac{1}{|\replaybuf|}
  \sum_{(q,a)\in\replaybuf}
  \sum_{j=1}^{|a|}
  \log p_{\params}(a_j\mid q,a_{<j}).
  \label{eq:sws_supervised_loss}
\end{equation}
When Oracle-derived targets or stability constraints are available, the trainer may optimize the more general objective
\begin{equation}
  \losssws
  =
  \loss_{\mathrm{sup}}
  +
  \lambda_{\mathrm{KD}}\losskd
  +
  \lambda_{\mathrm{stab}}\loss_{\mathrm{stab}},
  \label{eq:sws_full_objective}
\end{equation}
where $\losskd$ distills Oracle supervision and $\loss_{\mathrm{stab}}$ penalizes drift from previously important parameters.
The parameter update is
\begin{equation}
  \params^{(t+1)}
  =
  \params^{(t)}
  -
  \eta \nabla_{\params}
  \losssws
  \left(\params^{(t)};\replaybuf^{(t)}\right).
  \label{eq:sws_parameter_update}
\end{equation}
In deployment, this update can be instantiated with LoRA or adapter-based fine-tuning, keeping most Cortex parameters frozen and making SWS feasible for resource-constrained models.

\subsection{Algorithm}
\label{sec:method:algorithm}

Algorithm~\ref{alg:hat} summarizes the complete wake--sleep procedure.
The key design choice is that abstraction, routing, authorization, and replay are separate operators.
This modularity localizes failure modes: uncertain but uninformative turns are dropped by triage, duplicate knowledge revises existing traces rather than inflating memory, and only accepted write decisions can cross the raw-to-curated boundary.

\begin{algorithm}[t]
  \caption{\HAT wake--sleep learning loop}
  \label{alg:hat}
  \DontPrintSemicolon
  \KwIn{Initial Cortex $\modeltheta^{(0)}$, Neocortex $\neocortex^{(0)}$, thresholds $\tau_w,\tau_{\oracle},\tau_r$, optional Oracle $\oracle$}
  \For{cycle $t = 0,1,2,\ldots$}{
    Collect wake interactions $\mathcal{D}^{(t)}$\;
    \For{each interaction $x=(c,q,y)\in\mathcal{D}^{(t)}$}{
      Estimate uncertainty $U(x)$ using Eq.~\ref{eq:logprob_uncertainty}\;
      \If{$U(x)<\tau_w$}{
        Skip abstraction and do not write memory\;
      }
      \Else{
        \If{Oracle is enabled and $U(x)>\tau_{\oracle}$}{
          Query $\oracle(c,q)$ and replace the replay target if a correction is returned\;
        }
        Triage the turn; if it is knowledge-bearing, extract traces $\{m_k\}_{k=1}^{K}$ as canonical $(q^{\star},a^{\star})$ pairs\;
        \For{each trace $m_k$}{
          Compute write decision $d(m_k)$ from Eq.~\ref{eq:write_decision}\;
          Embed $q_k^{\star}$ and retrieve nearest memory by Eq.~\ref{eq:nearest_memory}\;
          Route by Eq.~\ref{eq:create_revise}: CREATE a new trace or REVISE the matched trace\;
          If $d(m_k)$ is accepted, apply the authorized Neocortex transition in Eq.~\ref{eq:neocortex_transition}\;
        }
      }
    }
    Sample replay batch $\replaybuf^{(t)}$ using Eq.~\ref{eq:priority_sample}--\ref{eq:replay_batch}\;
    Update Cortex parameters with the SWS objective in Eq.~\ref{eq:sws_full_objective}\;
  }
\end{algorithm}

\subsection{Discussion: Why the Separation Matters}
\label{sec:method:discussion}

HAT deliberately avoids conflating three questions that are often merged in continual-learning systems.
First, \emph{eligibility}: uncertainty determines whether the interaction is worth spending consolidation compute on.
Second, \emph{semantic identity}: embedding similarity determines whether a trace expands memory coverage or revises an existing concept.
Third, \emph{parameter adaptation}: SWS replay determines how accepted memories affect the Cortex.
This separation yields a practical continual learner whose memory is sparse, auditable, and replay-ready, while leaving the online model stable during user interaction.
